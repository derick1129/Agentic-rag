# CI Green Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restore trustworthy CI by fixing the reported unit and Compose contract failures, all Ruff findings, format and mypy failures, and independent quality reporting.

**Architecture:** Keep runtime services and supported adapters as they are; correct tests to match the current Redis/PostgreSQL API path. Repair source findings in focused module groups without suppressing rules, then ensure CI captures each quality command's result even when another command fails.

**Tech Stack:** Python, pytest, Ruff, mypy, Docker Compose, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-13-ci-green-design.md`

## Global Constraints

- `uv run ruff check .`, `uv run ruff format --check .`, `uv run mypy adaptive`, and the complete unit/smoke test commands must pass.
- Fix reported source issues; do not satisfy this requirement with repository-wide ignores, blanket per-file suppressions, or removal of checks.
- OpenSearch must not be added as a Compose runtime dependency unless the API path is changed to use it.
- Keep the separately supported OpenSearch adapter and its integration job only if the integration tests exercise that adapter.
- The quality job must run Ruff check, format check, and mypy even if Ruff check fails.
- Do not add an evaluation dataset, retrieval/answer quality thresholds, or evaluation CI gates.

## Review Focus

- Provider fakes must match keyword-only provider arguments — test `test_embedding_router_uses_nearest_seed` in Task 1.
- Compose assertions must reflect actual services and health dependencies — test both Compose contract tests in Task 1.
- Automated lint fixes must not alter runtime behavior or hide meaningful rules — run focused tests after each source group in Tasks 2–5.
- Type repairs must preserve runtime contracts and narrow optional handling — include representative module tests in Task 6.
- A failing quality command must not hide the other quality results — validate the workflow structure and run each command independently in Task 7.
